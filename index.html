How the calculations work

Input / Output / Cache Tiers

Baseline values match Cursor’s models & pricing docs. Fast and Auto modes appear as separate rows. Enabling High simulation in this dashboard applies \( \phi = 1.50 \) across Input, Cache Write, Cache Read, and Output for what-if math only — it is not Cursor Fast mode.

Cost Multiplier Factor (\(M\))

The pricing multiplier indicates how expensive a model's base input rate is compared to Auto Balance (\( C_{base} = \$2.50 \) per 1M tokens, twice the Auto Cost input rate — see the Auto modes card): $$M = \frac{C_{input}}{C_{base}}$$ Auto Balance is \( 1.0\times \). Auto Cost sits below that; Fast and Opus-class rows sit above. Values less than \( 1.0\times \) highlight budget-favorable processing states.

Simulated Cost (\(S_{cost}\))

Determined dynamically by matching custom slider inputs for Input Tokens (\(T_{in}\)), Output Tokens (\(T_{out}\)), and Cache Match Ratio (\(R_{cache}\)): $$S_{cost} = \frac{T_{in}}{10^6} \left[ (1-R_{cache})C_{in} + R_{cache}C_{read} \right] + \frac{T_{out}}{10^6}C_{out}$$ When Cursor publishes no cache-read rate, the simulator applies the standard input rate to cached tokens instead of treating them as free.

Speed

A 0–100 editorial estimate of relative responsiveness, not a vendor metric — Cursor publishes no speed number. Smaller variants (Nano, Mini, Haiku, Luna, Flash, Composer) rank high; Opus-, Sol-, and Fable-class reasoning models rank low. A Fast row always ranks above its standard twin, since Fast mode buys latency at a higher per-token rate. Treat it as ordering, not as tokens per second.

Auto Modes & Cursor Token Rate

Auto Cost bills fixed per-token rates whatever the router picks. Auto Balance and Auto Intelligence instead bill at the routed model's own API rate, and Cursor deliberately hides which model served a request — so no honest row can quote a single model's price.

The router picks among Composer 2.5, Grok 4.5, GPT-5.5, Claude Opus 5, and Claude Fable 5. The only cost figure Cursor publishes is that Balance and Intelligence average about \( 2\times \) Auto Cost and reach \( 2\text{–}4\times \) depending on mode, so those two rows are Auto Cost scaled by \( 2\times \) and \( 4\times \): $$C_{routed} = C_{auto\,cost} \times m, \quad m \in [2, 4]$$ Both modes need Cursor Router, which is Teams and Enterprise only. On those plans a third-party route also adds a Cursor Token Rate of \$0.25 per 1M tokens on top of the model's API price; the table excludes it, and Auto Cost plus first-party Grok 4.5 and Composer 2.5 are exempt.

Overall (\(E_{overall}\))

A single 0–100 number, computed per row rather than stored, weighing coding bench against cost efficiency: $$E_{overall} = (B_{code} \times 0.65) + \left( \left(1 - \frac{\min(M, 15)}{15}\right) \times 100 \times 0.35 \right)$$ It uses base input rates, so toggling High simulation does not move it. Speed is reported separately and is deliberately excluded, so a cheap fast model does not outrank a capable one on this column alone.
